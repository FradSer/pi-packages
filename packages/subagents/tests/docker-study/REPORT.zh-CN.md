# Pi 1.0.4 / DeepSeek v4.1 Flash 实测

2026-10-07。在两个独立 Docker 容器中运行当前工作区源码，使用真实的
`cli-proxy/opencode/deepseek-v4.1-flash` 推理，合计 152 次上游请求。
严格对照镜像为 `subagents-study:946c57ab4168e696`；CLI、pi-kit 和 subagents
解析到的 Pi SDK 都是 **1.0.4**。上游传输错误为 0。

结论：本轮没有复现临时／固定身份的启动、复用、关闭失败。固定身份的历史和
Memory 存储、正文读取确实工作；本轮没有证明 Memory 改善审查质量。
“同类任务反复出现后才创建固定身份”和“只读 reviewer 的经验自动进入有效记忆”
目前都缺少运行策略，不能用底层执行测试通过来替代这两项能力。

## 运行与身份

每轮分别运行三次临时身份、三次固定身份，每次执行两轮输入：

- 12 次输入全部收到有效结果，完成后状态均为 idle。
- 六次停止均确认关闭；停止后的旧句柄输入全部被拒绝。
- 另一个执行中的 next 输入返回 queued，随后两次输入各完成一次。
- 固定身份停止后，在同一父会话分区重启，正确恢复上一轮 `SECOND_OK` 回答。
- 不存在的固定身份、固定身份与临时 instructions 混用均在启动前拒绝。
- 每轮直接执行器共收到 25 个最终结果，input ID 均唯一；最终 roster 全部 stopped。

真实父模型另在原生 PTY 中完成四个请求：三次明确要求新的临时 reviewer，
三次都没有传 identity；第四次明确指定已有 learned-reviewer，正确选择固定身份。
展开快捷键和从 100 列调整到 60 列均产生重绘记录。这验证了明确指令下的选择和
原生终端交互，不证明模糊任务分类可靠，也不等同于全面像素／布局验收。

## Memory 的实际证据

只读 reviewer 的 `agent_memory append` 被拒绝；`propose` 成功写出候选文件，
该候选没有成为有效条目。源码中，`listAgentMemoryRoots` 仅被定义／导出，未找到
消费 Agent Memory 候选并完成自动审查、合并的生产运行路径。

训练阶段显式授权测试身份具有 write 权限，真实模型读取训练例子后调用
`agent_memory append`，生成一条审查方法。方法涉及异步交付、关闭确认、打包资源；
条目、派生索引和状态文件均保存。它是模型生成的条目，不是测试直接写入的答案。
但训练请求明确要求记录方法，因此它不证明无人提示的自动学习。

严格对照使用**同一个固定身份、同一份站立说明、相同任务和源码、相同实际工具
集合 read + agent_memory**。控制组执行时暂时隐藏有效 Memory，结束并确认关闭后
恢复原目录。各组使用新的父会话分区，排除训练对话历史的影响。

| 留出用例 | 无 Memory | 有 Memory |
| --- | --- | --- |
| 异步交付未处理 Promise | 正确识别 | 正确识别 |
| 原生关闭确认前释放所有权 | 正确识别 | 正确识别 |
| 运行时提示文件未打包 | 正确识别 | 正确识别 |
| 正确实现的负例 | 无误报 | 无误报 |
| 总计 | 4/4，零误报 | 4/4，零误报 |

有 Memory 组四次均有原生 read 工具成功返回完整条目正文的证据；控制组四次均无
Memory 索引注入。计分不是根据模型自称“使用了记忆”。首轮临时身份控制组也同样
4/4，但实际工具集合不同，因此质量结论以严格对照为主。

这组简单合成用例的基线已达到上限，无法显示质量提升，也不足以判定 Memory
没有长期价值。应在真实 package 审查的跨文件、跨会话留出任务上继续测量遗漏、
误报及验证质量；不能把“读到了文件”当作收益。

## 重复任务创建策略的缺口

当前 agent_start 只选择已有磁盘身份或启动临时角色；没有任务类型复用计数、
创建门槛或自动定义创建流程。工具不会将临时角色自动提升为固定身份，临时对话
也不能通过事后写 agent.md 追溯转成固定历史。

建议后续策略围绕独立任务请求的复用证据，而不是子输入、重试次数或显示 label：

1. 首次出现的任务类型使用临时角色。
2. 同类独立请求再次出现时记录复用证据和稳定的方法、权限需求。
3. 达到用户选择的创建条件后，形成可审阅的角色定义；已有固定身份正常复用。
4. 只读 reviewer 保持只读，经验进入候选；由独立审查／合并环节形成有效 Memory。
5. 有效记忆必须有适用条件、限制和验证证据，并在新的真实任务上测量作用。

本次没有修改身份创建策略，也没有将测试身份安装到真实用户配置。创建条件及
是否自动创建仍待用户选择，不能假定重复三次就是授权或合适的门槛。
