# Refine typography

Adapted from Impeccable `skill/reference/typeset.md` at `63b04e2530f5c7b41ea83c133daab24f34912456`, Apache-2.0. Modified for Pi: canonical taste replaces duplicated numeric rules; unsupported detector flags, native links, subagent and live-mode handoffs are removed. See package licenses and notices.

Follow [setup](setup.md), then [typography](../references/taste/typography.md) and its required shared constraints. Preserve established identity; replacing a font family or visual world requires that scope from the user.

First inspect authoritative faces, available weights, role hierarchy, repeated styles, actual reading conditions and font delivery. Cite source selectors or computed values. Keep this judgment independent of the static scan so heuristics do not determine the design. Test representative long headings, narrow containers, localization, zoom and fallback fonts.

Before editing, name the required roles, contrast between roles, reading density, authoritative assets and performance constraints. Use canonical typography rules for exact measures, leading, sizing, language and platform exceptions rather than introducing another scale. Keep only roles and font assets the interface consumes; do not invent a family for variety.

Apply the smallest coherent correction across equivalent roles. Verify actual loaded faces and fallbacks, font licensing, legibility, wrapping, numerical content and user text settings. Native requests require a verified platform supplement rather than web substitutions.

Inspect relevant sizes and loading states in one batch, fix observations, then confirm at most once. Use setup's supported local-file detector once where useful; it cannot establish typographic quality. Report rendered versus source-only evidence, untested states and remaining issues. Do not automatically start polish, agents or variant previews.
