# Clarify interface language

Adapted from Impeccable `skill/reference/clarify.md` at `63b04e2530f5c7b41ea83c133daab24f34912456`, Apache-2.0. Modified for Pi: the canonical writing and accessibility topics own detailed rules; automatic polish handoff is removed. See package licenses and notices.

Follow [setup](setup.md) and [writing](../references/taste/writing.md). Preserve factual meaning, domain terminology and brand voice. Ask before changing legal meaning, claims, causes or promises the implementation cannot establish.

Read the entire interaction path, not isolated strings. Identify ambiguous actions, jargon, missing consequences, inconsistent terminology, redundant introductions and recovery gaps. Infer audience and emotional context from product evidence rather than inventing them.

For each state, decide the fact needed now, the next available action, supporting context that changes the decision and an appropriate tone. Say each idea once. Follow the canonical writing owner for actions, forms, errors, permissions, loading, empty and success states, localization and accessible labels; do not duplicate those requirements here.

Rewrite the smallest useful scope. Keep complete translatable messages and structured dynamic values. Check the underlying behavior before promising recovery, progress or success. Do not silently change validation rules to fit an example message. A glossary is appropriate only when repeated inconsistency warrants it.

Verify comprehension, factual accuracy, recovery, terminology, consequence-appropriate tone, target widths, zoom, long names, pluralization and announced state changes. Inspect in context in one batch, fix observed problems and confirm at most once. Distinguish tested behavior from source-only review. Report meaningful changes and remaining questions; do not start another command or agent automatically.
