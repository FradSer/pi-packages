# @fradser/pi-open-deskos

把本机的 Pi 会话及其运作事件上报给 Open DeskOS。

[English](README.md) | **简体中文**

Open DeskOS 通常靠扫描来发现 Pi 会话：本地扫，或经 SSH 扫。这个方向不一定可用，而且扫描看不到会话到底在做什么。本 package 把它反过来：拥有会话的那台机器主动打开一条 **Desk Link**，自己上报。

## 安装

npm 包尚未发布，因此先从仓库按路径安装：

```bash
cd ~/.pi/agent
pi install ../../Developer/FradSer/pi-packages/packages/open-deskos
```

路径以 Pi 的设置目录为基准记录，所以要在该目录下运行。

`@fradser/pi-open-deskos` 发布之后，改用 `pi install npm:@fradser/pi-open-deskos` 即可。

## 配置

地址与 token 必须同时提供，机器才会开始上报；只配一半会保持静默。运行 `/open-deskos` 查看配置提示。

```bash
export ODK_DESK_LINK_ADDRESS="192.168.88.161:8765"   # Open DeskOS Desk Link Service
export ODK_DESK_LINK_TOKEN="<每连接一个 token>"
export ODK_DESK_LINK_MACHINE="desk-mac"              # 可选，默认取主机名
```

写进 Pi 运行时的环境里（桌面会话就是启动 `pi` 的那处）。

## 上报内容

- 当前会话的实时身份、目标、activity 和事件，以及本机 `directory-sessions` 中已有的其他会话元数据（由 `pi-utils`、`pi-keyboard` 写入）。UUID 与带时间戳前缀的 UUID 会合并为一个会话。
- 会话状态：元数据表示工作中、Pi 进程存活、时间戳匹配该进程生命周期时才为 `running`；存活的 idle/settled 会话为 `settled`。已结束、无效、被复用、无法核实的 PID 或明确退出的记录为 `exited`。每次扫描只读取一次有界进程表（1 MiB，2 秒超时），同一 PID 只有最新且无歧义的会话可视为存活。当前会话以 Pi 自身的 idle/agent 事件为准。
- 元数据原始的启动、更新时间，以及可选的名称、目标和 activity/recap。扫描不会刷新活动时间，也不会读取会话历史文件。
- 有界事件流：每会话保留最新、连续的事件尾部，最多 60 条且文本与工具名合计不超过 262,144 UTF-8 字节。用户、思考、工具调用和助手事件仍为最多 200 字符的单行摘要。
- 工具结果保留完整的多行 Markdown，包括表格、代码围栏和空白，每条正文最多 65,536 UTF-8 字节。所有文本块以两个换行连接；图片与任意结果元数据不上报。超过字节上限时会带 `truncated: true`，且不会截断 Unicode 码点。可选 `toolName` 为独立的 200 字符摘要，不再作为前缀插入 Markdown 正文。会话 activity 仍为简短的首行摘要。

清单在会话启动时扫描，此后每次扫描完成 5 秒后刷新，断链期间也继续。刷新只替换发现的条目，旧元数据不能删除或覆盖当前会话的身份和事件。关闭或重载时会取消刷新定时器，使待完成扫描和重连回调失效。

最多上报 64 个会话。只有当前会话固定保留；其余按 running、settled、exited 顺序优先，再按时间排序。曾直接观察的会话被其他进程恢复时，可由更新的元数据刷新状态，同时保留已有事件。容量上限允许淘汰旧历史及其事件，并非归档。

单次扫描最多遍历 256 个工作区、2,048 个 JSON 文件、8,192 个目录条目，每文件最多读取 16 KiB。损坏、超大、链接和非普通文件会跳过。名称、目标和 activity 各上限 200 字符，必要时在线协议中进一步缩短，尽量满足 65,536 字节的快照预算。会话 ID、完整工作目录、workspace 名称和时间戳不会缩短或合并。若身份字段仍超过预算，会从该快照省略优先级最低的完整条目，`/open-deskos` 显示省略数量，当前会话固定保留。若单个当前会话的身份字段就超过预算，在不改写身份的前提下无法表达，这仍是极端限制。

默认读取 `~/.pi/agent/directory-sessions`。可用 `PI_DIRECTORY_SESSIONS_DIR` 指定注册表；否则 `PI_CODING_AGENT_DIR`（或旧的 `PI_AGENT_DIR`）覆盖 agent 目录。元数据写入端必须使用同一目录。发现过程不修改、清理注册表文件。不凭空创建没有元数据的会话；被删除的元数据会在下次刷新消失，除非本上报端曾直接观察该会话。

## 不上报什么

- **不可管理。** v1 只上报。package 从不发送 prompt、不阻塞回合、不修改消息；通过 Desk Link 可见**不等于**可管理。
- **无网络发现或配对。** 会发现本地会话元数据，但不知道地址与 token 的机器仍无法注册。
- **不扫描历史或凭据。** 不读取会话历史、认证文件或任意额外元数据。其他会话只贡献注册表元数据，不伪造事件。当前会话的工具结果文本**会在上述上限内发送**，其中可能包含工具返回的文件内容或敏感输出；仅在同意共享这些内容时配置链路。
- **无加密。** Desk Link 是连到仅 LAN 监听的普通连接，token 是唯一门槛。不要把 Desk Link Service 暴露到局域网之外。

## 在 Pi 里查看链路状态

```
/open-deskos
```

显示链路状态、机器标识、连接地址、上报会话数、事件数，以及最近的连接错误（如有）。诊断信息仅通过命令查看：Open DeskOS 不添加页脚状态行、自定义页脚或工作目录后缀，离线或未配置时也一样。

## 断链行为

上报端以递增等待重连（1s、2s、4s……上限 30s），并始终只保持一条链路。历史与待发事件均受每会话 60 条 / 262,144 字节上限约束。每次新连接都会发送当前会话状态，重放完整的已保留事件尾部，即使离线期间没有新事件也一样，因为服务端可能在最后一条链路关闭后清除机器状态。此连接后续刷新只发送新事件。

版本 1 没有事件 ID 或重放确认。如果其他链路维持了服务端的机器状态，重连重放可能产生重复事件，不保证恰好一次交付。重放始终有界，并非会话归档。

## 线协议

一条 TCP 连接上的换行分隔 JSON，版本 1。清单发现的会话带 `discovered: true`，当前会话直接观察的记录不带该标记，使服务端优先采用活动中的直接观察，而非其他上报端读取的更晚元数据。上报端写 `hello`、`sessions`、`events`、`bye`；服务端可回 `ack`、`error`，以及一个尚无实现的保留 `prompt` 记录。分帧只按 LF，并容忍尾部 CR。结果事件的 `text` 为原始 Markdown，可带 `toolName` 和 `truncated: true`。追加式 `events` 记录按完整事件拆成每帧最多 1 MiB 的批次，上限包括 JSON 转义和末尾 LF；不会为适应帧大小而拆分、压平正文。替换式 `sessions` 快照仍使用独立的 65,536 字节生产端预算。若完整身份字段导致单条事件无法装入一帧，该事件不会发送，命令会显示帧上限错误。
