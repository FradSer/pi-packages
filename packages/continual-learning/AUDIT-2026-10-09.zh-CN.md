## 提示词与工具设计反思

### 保留当前明确的命令边界

管理动作留在命令和原生菜单是合理的。没有必要把模型选择、策略切换、undo 确认再包装成 LLM 交互工具。父进程校验与写入分离也应保留。需要补强的是读权限、事务所有权和结果反馈，而不是增加工具数量。

### 把数据权限与提示词措辞分开

`before_agent_start` 每次把 Memory 文件名、description 和根路径追加到 systemPrompt（`inject-memory.ts:2461`）。正文不注入、总量有预算、内容标为 untrusted，这些措施有价值。但是 description 仍由共享文件内容提供，和包拥有的指导同处系统提示词；单行化与 “untrusted” 文案都不等于模型级安全隔离。

建议固定系统层读取协议，把可变索引作为带来源的参考消息投递，并测试恶意 description、正文、工具结果及嵌入计划的实际诱导效果。当前没有证据证明这种角色调整能单独解决注入；它也会改变缓存、分支、压缩行为，应通过配对实验判断。更紧迫的是 Findings #3 的确定性读取授权。

Harness text 指导按 retained context 去重、增量尾部投递，并排除自己的输出作为触发源；保留这套设计。历史关键词仍可触发指导，因此 scoped 文案只能表达适用范围，不能证明模型遵守了范围。skill/text 指导和 Bash 执行门需要继续分别报告。原始 Bash 正则不是 shell 执行树，已有 README 正确说明此限制。

### 管理面板应支持阅读与决策

Memory 正文预览上限 4,000 字符，历史总体预览上限 8,000 字符；Harness 详情也裁剪。当前通知加 Close 菜单适合短内容，但不是完整阅读器。建议提供可滚动详情、完整文件路径与分页差异；保留裁剪提示。视觉上是否被通知/菜单遮挡，本次没有截图证据，不列为已确认缺陷。

proposed 历史只有 Close，无法直接接受原提案；README 明确规定 `/consolidate` 重新生成新计划，因此不应把它误报为遗漏的实现。仍需给用户提供明确下一步：原因、需要补充的证据、可重跑命令。若要实现接受/拒绝，必须重新验证原计划、证据、目标版本及权限，不能绕过当前父进程边界。

### 限量证据不能成为完整性声明

Task Slice 限制为 96 条、512,000 字节，保留第一条和后部条目并记录 omittedEntries（`incremental-learning.ts:172`）。这限制成本，但遗漏的中段可能包含撤销或例外；当前 Jev 对“全部原始证据”的覆盖，是对传入 slice 的覆盖。建议 receipts 显式呈现截断，并对会删除知识、扩大限制或长期固化结论的操作采用更保守的策略。尚未复现真实模型因遗漏而错误应用，所以列为待验证设计风险。

### 学习效果用净收益验收

现有 1,115 项测试说明大量结构、隐私、引用、rollback 和生命周期契约可以自动验证；不能据此宣称 Memory/Harness 已提升真实任务能力。包内研究报告保留了 availability、preflight false positive、proposal friction、不同 provenance 不可直接配对等限制，应继续保留这些限制。

下一轮评价至少把任务成功/回归、Memory 读取命中、错误知识、误拦截、主模型与 Jev 总延迟/成本、人工处理 proposal 的负担放在同一配对实验中。本次没有重新调用真实模型或复跑 Docker/held-out 研究，历史结果只作为既有证据记录。

### 维护成本

`inject-memory.ts` 2,639 行，同时负责配置、命令、渲染、调度、子进程协议、修复、验证与应用。研究与运行代码的边界较复杂。优先抽出稳定且可独立验证的事务/worker 协议，而不是为了行数拆文件。对长期保留的 run snapshot、stdout/stderr、history 应明确保留策略；本次没有测量实际磁盘累积，不宣称已经发生容量故障。
