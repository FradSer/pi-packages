# Product integration of independently usable Memory

The ordinary consolidation pipeline now requests the existing independent and
standalone proofs when Jev is enabled. This addresses real missed learning:
a mixed plan can contain verified reusable knowledge and an unrelated held
candidate. Only an authorized apply policy and unchanged pure-create candidates
can reach subset persistence; all original support/counterevidence, relationship,
privacy, frozen-state and transaction checks remain required. The parent requests
additional proof only when some candidates passed and others remain held, both
before and after its single bounded correction. Identical corrected plans and
reviews reuse the earlier no-subset decision rather than repeating service calls.
Historical `composed` experiment copies now contain the same production source as
`default`; they no longer represent distinct Memory policies.

Held records remain pending and the original proposal is retained. Partial writes
are not complete learning. A subsequent task may retrieve the verified records;
this mechanical delivery must still be distinguished from measured task benefit.
The direct judge factory retains its programmatic opt-in contract. Historical
experiments below used flags explicitly before the ordinary pipeline adopted it.

# Earlier isolated integration contract

`createJevJudge` accepts the two programmatic evaluation flags
`independentMemoryApplication` and `composedMemoryApplication`. Both must be true
for additional standalone requests. Ordinary unified user configuration exposes
neither flag; default construction stays unchanged. No slash command is added.

The existing complete original support/counterevidence review and all pair
observations remain prerequisites. Full original evidence, candidates, privacy,
citations, support checklists, existing bodies and hashes are checked before
collection. Each standalone request includes all frozen originals and its
complete target body and description. At most five targets and four concurrent
requests are permitted; each wire is bounded to 64,000 bytes. Extra requests use
an explicit per-call timeout capped at five seconds, preserving a shorter client
timeout, with no retries. The actual model must match the pinned original review.

The diagnostic proof retains every original candidate index and digest, original
evidence/candidate/existing digests and actual model. Uncertainty cannot add
readiness. Extra service failure preserves the original pair review for fallback;
a dossier mutation invalidates the original review too. No diagnostic grants
write authority. The parent checks its frozen inputs after the awaited collection
and only passes the extra proof when its programmatic composed gate is enabled.

The parent persists the full original proposal before validating or writing the
unchanged subset. Existing permission, privacy, schema, Python validation,
receipt validation, transaction rollback and pending operation accounting remain
mandatory. Standalone telemetry is recorded as a no-op diagnostic until an actual
proposal or write occurs. The receipt reports a controlled strategy, reason,
actual model, latency and known/unknown usage; no sensitive source text is added.

Tests include old-parent RED (0 operations instead of 2), bounded complete
collection, no-default-call, full original data, unknown/model mismatch/mutation,
privacy/stale rejection, per-call timeout, and default parent gate denial.
Native Docker arms use identical fixed main and semantic response policies and
separate programmatic gates. They prove runtime behavior and writes, not real
model quality. Actual Jev and specified main-model project evaluation remain
required; no default activation or goal completion is claimed.
