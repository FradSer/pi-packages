# Prospective research: independent new Memory proposals

Status: a read-only subset simulator has offline regression coverage. Partial
application is not implemented or adopted. Existing whole-plan hold stays in force. Optional Jev's overall quality improvement remains unproven. Independent
review of current code found this is a documented behavior-contract change and
requires proof of independence before any durable operation.

R12 mitt/on second Memory attempt had one reported description counterevidence
failure. Current full answer iteration can distinguish other candidates' existing
checks, but neither telemetry nor candidateFailures complement proves independent
writing safe. Existing relation checks compare existing Memory, not new candidates
against one another. This evidence supports investigation, not permission to write.

Proposed bounded scope, subject to verification:

- Only pure new Memory with original operations empty. Existing selected Memory
  must remain included in semantic checks. No rewrite/delete/rename, mixed plans
  or Harness partitioning.
- Keep original thresholds and complete support, body, description, relationship
  and every counterevidence window. Disabled/unavailable/timeout/cancelled, bounds,
  sensitive data, denied permissions or missing/mixed-model response means no
  partition proof and original whole-plan hold.
- Semantic judge supplies a distinct complete-review result bound to original
  evidence digest, existing dossier digest, whole candidate digest and exact
  original indexes. It must confirm each expected check, never use telemetry
  complement as authorization.
- Candidate pair dependency/conflict/duplicate checks precede independence proof.
  Unresolved or dependent candidates stay together as proposals; no unsupported
  inference from original evidence alone. New external checks need prospective
  budget and privacy/preflight validation.
- Parent alone decides permissions. Persist original intent and held proposals
  before writing an accepted subset; persistence failure holds everything. Rebind
  derived plan digest and run existing structural/source/identity/name validation.
  Accepted subset applies in one existing rollback-capable transaction including
  body, safe mirror and index. Do not skip failed items inside an apply loop.
- Receipt distinguishes accepted and held counts, reasons and known partial model
  usage without candidate/private original text. Later review rereads original
  bound evidence and current Memory corpus; no stale decision replay.

Required Given/When/Then and RED/GREEN cases before implementation:

1. Independent A passes all checks; B description uncertain: proposed proof can
   accept A only after held B is safely preserved and parent validation passes.
2. A depends on B, conflict, duplicate or unknown pair relation: no unsafe subset.
3. Candidate/evidence/existing dossier/source role changes: identity fails closed.
4. Incomplete window/request/model, cancellation, missing auth or privacy refusal:
   existing whole-plan hold, never infer a no-learning opportunity.
5. Held proposal persistence failure: no accepted subset writes.
6. Body/index/mirror failure: rollback complete; original intent survives.
7. Manual Memory: held request visible and durable proposal retained; no Harness.
8. Legacy rewrite/delete/mixed plans/Harness: unchanged all-or-propose behavior.

Evaluation must preserve old full-plan results. Fresh bilingual multi-candidate
labels should measure accepted supported candidates, erroneous writes, held valid
candidates, lost explicit intent and actual usage/latency. Never relabel existing
plan-level frozen corpora to manufacture an apparent gain. Include fresh heldout
and actual isolated Pi/Docker workflow evidence before adopting or declaring the
full optional-Jev goal complete.

## Offline subset simulation

@tests/independent-memory-subset-research.ts computes original candidate indexes
only; it returns `writeAuthorized: false` and no plan or candidate text. It
requires the exact diagnostic review checklist (body, description, existing
relationship, every evidence window), unchanged source/dossier/candidate digests,
original source citation and privacy normalization, full original privacy/bounds
preflight, actual evidence window count, and every unordered original
pair exactly once with the same actual `jev-1.13.0` version. Existing pair
confidence 0.8 and winning probability 0.9 remain unchanged.

Only fully supported records whose every pair is decisively independent can be
counted as recoverable. Dependency, conflict, duplication or uncertainty holds
both endpoints; missing, stale, malformed or mixed-model proof holds the whole
set. All original indexes remain recoverable or held, preserving explicit intent.
This intentionally does not recover a dependent group, even when both records
pass support, because grouped safety has not been established.

The simulator is not imported by the plugin or bundled for release. Its synthetic
unit tests are control-flow and identity evidence, not new Jev inference or a
quality improvement. Previous three relation studies remain negative and are not
reclassified. Before any partial application, fresh prospectively labeled full
batches need real complete-candidate and pair judgments, followed by the proposal
persistence, transaction, permission and end-to-end checks above.

The simulator reruns the production preflight using an intentionally failing
local fetch callback. No request is forwarded and no mock semantic answer is
used as support. This derives the original window count and checks full evidence
and existing Memory privacy/capacity, rather than trusting a caller's checklist
size. Private Memory eligibility requires explicit `allowPrivateMemory: true`;
local input identity is checked again after the asynchronous preflight.

Each arm used one local fixture response; both owned containers are absent.
