# Jev 学习判断设计反思与真实回放

后续生产实现、完整反证审查与新增真实结果见 @jev-cited-evidence-evaluation.md。
以下描述的是当时只读研究阶段，不代表当前生产实现。

2026-10-05。本报告承接 @jev-expanded-evaluation.md 的三轮、18 次独立 Docker
执行。它研究改进方向，不声称已经修复 Jev 开启组的全部实际学习失败。

## 结论

存在可测量的改进方向：把 Jev 的任务改成小而明确的证据判断，减少候选扩写，
并让证据检索与反证检查成为父进程管理的显式步骤。继续把整段任务轨迹交给
Jev、要求它一次认可多个混合主张，容易让正确事实也停留在提案。

不过，仅缩短候选还不稳定；仅筛选引用上下文又不能证明安全。生产实现没有
改成丢弃工具证据、自动接受不确定结果或直接写文件。本轮只增加只读研究评估器、
其输入授权检查与测试。

## 原有结果能说明什么

- 三轮各自冻结不同源码版本；18 次执行不是同一个版本的18次独立抽样。
  同一个项目的开启/关闭组由大模型分别生成代码轨迹与候选，不能单独归因于 Jev。
- 最终 Click 开启组在本地容量检查停止，未获得相应模型判断。107 KB 的冻结证据
  不能塞进64 KB请求限制。这个失败首先是接口与工作流形状问题。
- p-limit、Mitt 的不确定结果并不等于“没有可学知识”。生成器经常把测试命令
  扩写成布局、历史执行数字和临时环境处理；一个候选乃至整个计划因此有多个待证主张。
- p-limit 关闭组未发出被禁止的 Bash 调用，不能把它的口头拒绝计为原生 Hook
  拦截证据，也不能据此推断 Hook 实际失效。
- 最后一轮 Docker 镜像早于最终的 Memory 内容/管理字段问题澄清。下面的回放
  使用当前判断器；并未对当前版本重新跑完整 Docker 生命周期。

## 同一冻结输入上的真实比较

@evaluate_jev_learning_design.ts 明确读取最终 Docker 开启组保存的三份 plan/snapshot。
计划和证据 SHA256 绑定允许列表，全部输入预检完才允许构造判断器；拒绝未知、
修改过或重复的样本。人工合成个人偏好只属于此前公开测试协议，未读取真实用户私有文件。
Jev 禁用不能被标成真实推理。输出只有哈希、大小、受控判断和用量，不存原文或密钥。

预先固定五种比较，不随结果修改标签：

1. 原生成候选 + 完整冻结证据：原候选没有逐条人工金标，不把所有提案都算误拦。
2. 三个最小候选 + 完整冻结证据：明确的测试命令、私人报告结尾、项目不推送偏好。
   三者都引用真实冻结用户原话，并经过现有结构/原文校验。
3. 同样的最小候选 + 研究用引用上下文：保留完整被引用用户消息及所有后续用户消息。
4. 在该研究上下文后追加命令纠正与报告偏好撤回：整个旧计划应留作提案。
5. 给候选加上无依据的 Node 999 与公开存放凭据要求：应留作提案。

原候选与最小候选同时改变内容、长度和数量，不能把差异单独归因于措辞简化。
第2、3种之间候选相同，改变的是判断上下文。研究上下文会丢失其他工具/助理条目，
因此所有结果均标记 `productionWriteEligible: false`；不能成为自动写入许可。

## 优先实现的设计

1. **减少生成器的扩写。** 每个新增 Memory 围绕一个明确事实，保留适用项目、
   时间范围、隐私和原始例外。引用不足的附加主张另成候选，不牵连正确事实。
   这仍需真实生成器测试，不能用本报告的手写最小候选代表生产生成质量。
2. **构造可追溯证据包。** 父进程保留完整冻结快照；验证引用后给支持判断提供原句、
   完整来源消息和身份。针对整个快照另外检查后续纠正、范围例外与矛盾，避免仅保留
   有利引用。长证据可以按完整消息边界处理，无法安全拆分或覆盖时继续提案。
   只有局部支持与完整反证覆盖都成立，才进入现有写入检查。
3. **分开判断不同问题。** “原文支持这个事实吗”“是否临时事件”“是否与已读
   Memory 重复/冲突”“是否扩大 Harness 约束”各自有明确输入与答案。
   可独立的问题批量执行；依赖正文的关系判断等正文读完再执行。不通过重试挑选
   一次高置信答案来绕过不确定性。
4. **避免无依赖候选相互拖累。** 可研究仅针对新增文件的独立候选提案/提交。
   父进程必须先证明文件、知识和权限没有交叉依赖，并重新检查冻结状态与锁。
   重写、删除和有依赖的操作继续保持原子性。未经这些验证，保持当前整批策略。
5. **不确定时补证据或保留提案。** 不把它解释为没有机会，也不取消原有 Harness。
   明确 `/memory <要求>` 始终进入处理，不改简单命令，不让 Jev 操作文件或隐私分类。

下一轮验收需要：固定候选的因果对照，加上全轨迹真实生成/写入/新会话使用的生态
测试；新增中英文未知样本；覆盖后续工具反证、撤销单项偏好、Memory冲突、超大单条
证据、私有权限以及部分候选的依赖。分别统计误记、误拦、未决、持久化、召回、
Harness真实执行、耗时和费用。仅模型返回允许不能算学习效果改善。

官方资料支持“小判断 + 明确上下文”的方向：
[State](https://docs.typesafe.ai/concepts/state)、
[引用检查示例](https://docs.typesafe.ai/cookbooks/citation_check)与
[Confidence](https://docs.typesafe.ai/confidence)。其中置信度描述答案分布，不能代替
工作流正确性和权限判断。本报告的架构选择是依据这些资料与上述失败提出的推断。
