# Frozen composed-readiness research protocol

Purpose: evaluate whether retaining original independent-subset successes and
adding strictly self-contained supported records recovers useful knowledge.
This is a read-only selection simulation, not a writer or full quality acceptance.

Before inference, freeze the policy, corpus, candidate bytes, original production
support/pair code, standalone code, SDK and lockfile. Use 18 fresh author-defined
samples (nine bilingual archetypes), independently review labels before calls.
Use Jev 1.13.0, SDK 0.6.0, confidence 0.8/probability 0.9, timeout 5 seconds,
retry zero, no favorable reruns. Maximum 90 external requests; each request
fits the unchanged 64,000-byte preflight and provider context limits.

Each case runs actual original full candidate support/body/description and
counterevidence review, actual original pair review and two standalone judgments.
Baseline and composed selection consume the same support and pair results.
Code validates full original checklists, citations, privacy, windows and bindings
using the existing offline simulation preflight. Standalone proof must cover all
original candidate indexes with exact digests and model version. Missing/stale
or malformed extra proof falls back to original selection, never adds a candidate.
An uncertain extra answer never contributes readiness. Original successes remain
available. A support-passed candidate can additionally be ready only after strict
standalone observation. Every pair inside the initial tentative ready set must
still be decisively independent; deletion order cannot eliminate that obligation.

Report useful knowledge cases recovered, unsupported facts selected, incompatible
or redundant selections, required knowledge held, original successes lost,
incomplete inference coverage, actual models, known token use and estimated cost.
Duplicate supported records are a quality counterexample: at least one useful
record should be recoverable; holding both is a miss, not a successful safety test.

Any unsupported/incompatible recovery, original success regression, incomplete
real coverage or nonpositive net recovery prevents promotion from this study.
Positive results can justify gated native-parent work, not user-default activation
or the claim that full project generation/application/recall quality improved.

Before paid inference, label review clarified same-batch Memory-note references
and connection-establishment timeout synonymy. A ninth bilingual positive case
checks that a stated location in an existing project file is useful standalone
knowledge and is not confused with a missing proposed Memory definition.
