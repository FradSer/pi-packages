`packages/agent-teams` is a run-centric multi-agent system: the Pi session is the leader; agents are declarative Markdown files; each run is a dependency-aware task graph dispatched in one call, where each node is a bounded child Pi process and a session-wide cap limits total workers to 8.

**Why:**
The teammate-registry model (runtime registration, task creation/start ceremony, session-scoped identities, and read receipts) was replaced after a design review. The ceremony critique: a one-off delegation cost four tool calls, identities were session-ephemeral so registration cost was paid per session, and single-call DAG dispatch plus declarative Markdown agents provided the simpler model. The later simplification removed the remaining half-channels: workers message only the leader, upstream DAG results replace peer delivery, and live run state is not injected into every system prompt.

**How to apply:**
1. **Agents are declarative files** (`src/agents.ts`): frontmatter `name`/`description`/`tools`/`model` (inline `#` comments stripped), body = role prompt. Discovery precedence per name: project `.pi/agents/` > user `~/.pi/agent/agents/` > bundled `agents/`. Bundled agents: worker/reviewer/specialist/observer.
2. **Single-call DAG dispatch** (`teammate_run`): `tasks` with `id`/`agent`/`prompt`/`paths`/`access` (default read)/`dependsOn`/`model`/`mode`/`turnBudget`/`forkContext`/`inputBindings`, plus `concurrency` (default 4), `worktree`, `background`, `summarize`, and `summaryAgent`. `turnBudget` is an assistant-turn cap with a default of 100; there is no run or node wall-clock deadline API. The scheduler validates duplicate ids, unknown dependencies, cycles, and invalid paths before spawning. Root nodes start immediately; `scheduleRun` auto-starts dependents on completion; overlapping shared-workspace writes are deferred across all runs in the session unless worktree-isolated.
3. **Scheduling metadata is not access control**: `paths` and `access` are included in prompts and used for overlap scheduling. Shared-workspace protection is advisory write/write coordination only. These fields do not enforce read/write permissions, and there is no OS or container sandbox. A worker's actual capabilities come from its resolved agent definition's `tools` list. `worktree=true` provides Git worktree separation and diff capture, not a general sandbox.
4. **Leader tools**: `teammate_run`, `teammate_fanout` for bounded fanout of a completed structured array, `teammate_message` for steering a running RPC worker, `teammate_cancel`, and `teammate_retry`. The leader has no peer mailbox or broadcast channel. Worker messages and leader steering share the `teammate_message` tool name but have distinct capability-bound parameters.
5. **Worker protocol**: worker-only `teammate_message` accepts `subject`/`body`, optional lifecycle status, and optional structured data; it always sends to the leader. Per-spawn identity uses `PI_TEAMMATE_WORKER_NAME = runId:nodeId` and a fresh `PI_TEAMMATE_SPAWN_ID`; `applyWorkerEvents` rejects stale-spawn events. Messages enter one leader inbox. Upstream DAG results are injected into downstream prompts (`=== UPSTREAM HANDOFF ===`); no worker-to-worker mailbox is used.
6. **Outcomes and non-polling leader**: workers send their deliverables through `teammate_message`, and background runs deliver automatic follow-ups. The leader does not sleep while tasks execute. One canonical terminal result per node is built by the harness after child close; a worker message alone is not final delivery. Failed nodes cancel their transitive pending dependents. A per-node Git worktree can capture a diff for integration review. State snapshots are dirty-gated and temporary worker task files are removed after close. Foreground gather (`background: false`) blocks inline, then detaches to background after its bounded gather period.
7. **UI**: passive widget (display-only) plus `/teammate` full-screen console (owns input via `ctx.ui.custom`, no global interception). Rows are nodes; detail shows node lifecycle and messages sent to the leader; live activity streams tool calls and thinking deltas. The console follows the `@packages/btw` style language and supports keyboard scrolling.
8. **Testing**: BDD in `features/agent-teams.feature`, package tests in `tests/test_teammate_package.py` including node-eval runtime tests of state.ts/spawner.ts; typecheck via `npx tsc --noEmit --strict ... src/*.ts`.
